# Ρουμπρίκες αξιολόγησης εργασίας

Σε όλες τις ομάδες προστίθεται ένα κοινό κριτήριο: **διαχείριση αλλαγών**. Όταν μια νέα προδιαγραφή αλλάζει κάτι, τα προηγούμενα παραδοτέα ενημερώνονται και η αλλαγή καταγράφεται στο CHANGELOG με τα επηρεαζόμενα στοιχεία.

Κάθε κριτήριο βαθμολογείται σε τρία επίπεδα: πλήρες (2), μερικό (1), ανεπαρκές (0). Ο βαθμός της ομάδας παραδοτέων είναι το ποσοστό των μονάδων επί του μέγιστου, πολλαπλασιασμένο με το βάρος της.

## Ομάδα Α · Quality plan, απαιτήσεις, ιχνηλασιμότητα (5%)

| Κριτήριο | Πλήρες |
|---|---|
| Κίνδυνοι | Συγκεκριμένα γεγονότα, ≥ 4 χαρακτηριστικά, αιτιολογημένη πιθανότητα και επίπτωση |
| Μετρησιμότητα | Κάθε μη λειτουργική απαίτηση έχει κλίμακα, μέθοδο, συνθήκες και όριο |
| Ποιότητα διατύπωσης | Ατομικές, μονοσήμαντες απαιτήσεις χωρίς λέξεις-παγίδες, σε EARS ή Planguage |
| Κριτήρια αποδοχής | Συγκεκριμένα δεδομένα, ένα When, σενάρια σφάλματος και ορίου |
| Ιχνηλασιμότητα | Κάθε κίνδυνος υψηλής προτεραιότητας καλύπτεται· κενά δηλώνονται ρητά |
| Μοντέλο ποιότητας | Αντιστοίχιση στο ISO/IEC 25010:2023 με τεκμηριωμένη προτεραιοποίηση |
| Αξιοποίηση review | Απόφαση με αιτιολόγηση για κάθε εύρημα |
| Ερωτήσεις και παραδοχές | Ουσιαστικές ερωτήσεις προς τη βιβλιοθήκη, ρητά καταγεγραμμένες παραδοχές |

## Ομάδα Β · Μετρικές, στατική ανάλυση, review (8%)

| Κριτήριο | Πλήρες |
|---|---|
| Μέτρηση | Σωστή εκτέλεση εργαλείων, αναπαραγώγιμη εντολή, καταγεγραμμένη έκδοση |
| Ερμηνεία | Οι αριθμοί συνδέονται με κινδύνους και απαιτήσεις, όχι απλή παράθεση |
| Ευρήματα στατικής ανάλυσης | Διάκριση true και false positives με αιτιολόγηση |
| Code review | Ευρήματα με τοποθεσία, κατηγορία, σοβαρότητα |
| Σχέδιο remediation | Προτεραιοποιημένο, με κόστος και όφελος |

## Ομάδα Γ · Σχεδιασμός test cases (8%)

| Κριτήριο | Πλήρες |
|---|---|
| Κλάσεις ισοδυναμίας και οριακές τιμές | Πλήρεις, με έγκυρες και άκυρες κλάσεις |
| Πίνακες αποφάσεων | Όλοι οι συνδυασμοί ή αιτιολογημένη σύμπτυξη |
| Γράφος ροής και βασικά μονοπάτια | Σωστή κυκλωματική πολυπλοκότητα και εφικτά μονοπάτια |
| Ιχνηλασιμότητα | Κάθε test case συνδέεται με απαίτηση |
| Αναμενόμενα αποτελέσματα | Συγκεκριμένα, από την απαίτηση και όχι από τον κώδικα |

## Ομάδα Δ · Αυτοματοποιημένες δοκιμές, integration/API, debugging (10%)

| Κριτήριο | Πλήρες |
|---|---|
| Ορθότητα tests | Ουσιαστικά assertions, κανένα test που περνά χωρίς να ελέγχει |
| Δομή | Fixtures, parametrize, ανεξάρτητα και ντετερμινιστικά tests |
| Test doubles | Κατάλληλη χρήση, χωρίς υπερβολικό mocking |
| Κάλυψη | Στόχος κάλυψης διακλαδώσεων επιτεύχθηκε ή εξηγείται η απόκλιση |
| Integration/API | Σενάρια ολοκλήρωσης με σφάλματα εξαρτήσεων |
| Debugging | Αναπαραγωγή, αιτία, διόρθωση, regression test, RCA |

## Ομάδα Ε · Performance, CI, quality gate (4%)

| Κριτήριο | Πλήρες |
|---|---|
| Σενάριο φορτίου | Ρεαλιστικό, με τεκμηριωμένες παραδοχές |
| Μετρήσεις | Εκατοστημόρια, ποσοστό σφαλμάτων, σύγκριση με απαίτηση |
| Ροή CI | Εκτελεί tests, κάλυψη και στατική ανάλυση σε κάθε push |
| Quality gate | Σαφή κατώφλια που αποτυγχάνουν το build όταν παραβιάζονται |

## Ομάδα ΣΤ · Τελική αναφορά και ατομική υποστήριξη (5%)

| Κριτήριο | Πλήρες |
|---|---|
| Σύνθεση | Συνεκτική εικόνα ποιότητας, από κινδύνους ως αποτελέσματα |
| Περιορισμοί | Ειλικρινής καταγραφή του τι δεν ελέγχθηκε και γιατί |
| Ατομική υποστήριξη | Κάθε μέλος εξηγεί και τεκμηριώνει τεχνικές αποφάσεις, και τα κομμάτια των άλλων |
