# Εργασία εξαμήνου: StudyRoom

## Το σενάριο

Η βιβλιοθήκη του Τμήματος διαθέτει αίθουσες ομαδικής μελέτης, και σήμερα οι κρατήσεις τους γίνονται σε τετράδιο στον πάγκο εξυπηρέτησης. Η βιβλιοθήκη έχει αναθέσει σε μια ομάδα ανάπτυξης ένα σύστημα κρατήσεων με το όνομα StudyRoom. Εσείς είστε η ομάδα ποιότητας του έργου. Δεν γράφετε το σύστημα: το προδιαγράφετε, το μετράτε, το ελέγχετε και τεκμηριώνετε τι ξέρουμε για την ποιότητά του.

Όλες οι ομάδες δουλεύουν στο ίδιο σύστημα. Το StudyRoom μεγαλώνει μαζί με το μάθημα. Την πρώτη εβδομάδα έχετε μόνο ένα κείμενο του πελάτη. Αργότερα έρχονται πρακτικά συναντήσεων, αλλαγές απαιτήσεων και, από την Εβδομάδα 4, ο κώδικας του συστήματος. Ακολουθούν pull requests για review, ένα HTTP API και, τέλος, αναφορές περιστατικών από την πιλοτική λειτουργία.

**Δημοσιευμένες εβδομάδες:** [Εβδομάδα 1](week01.md) · [Εβδομάδα 2](week02.md) · [Εβδομάδα 3](week03.md)

## Πώς είναι οργανωμένη

Κάθε Δευτέρα δημοσιεύεται ένα αρχείο `weekNN.md` σε αυτόν τον φάκελο, με δύο μέρη. Το ίδιο περιεχόμενο, σωρευτικά για όλες τις εβδομάδες, βρίσκεται στο [`StudyRoom_ergasia.docx`](StudyRoom_ergasia.docx), που ενημερώνεται με νέα έκδοση κάθε εβδομάδα. Οι **προδιαγραφές** προσθέτουν ή αλλάζουν κάτι στο σύστημα. Μπορεί να είναι νέο κείμενο του πελάτη, απάντηση σε ερωτήματά σας, κώδικας ή αλλαγή που ακυρώνει κάτι προηγούμενο. Τα **ερωτήματα** ζητούν να εφαρμόσετε στο StudyRoom τις τεχνικές της διάλεξης. Οι προδιαγραφές μιας εβδομάδας ισχύουν και για όλες τις επόμενες, εκτός αν κάποια μεταγενέστερη τις αλλάξει ρητά.

Στο εργαστηριακό σκέλος της Δευτέρας ξεκινάτε τα ερωτήματα της εβδομάδας στην αίθουσα. Πρώτα βλέπετε την τεχνική λυμένη στο σύστημα αναφοράς `foodorder` (`labs/weekNN/SOLVED.md`) και μετά την εφαρμόζετε στο StudyRoom. Τα ερωτήματα ολοκληρώνονται στο σπίτι.

Η δουλειά κάθε εβδομάδας πατά στην προηγούμενη. Ο κατάλογος κινδύνων της Εβδομάδας 1 γίνεται πηγή απαιτήσεων την Εβδομάδα 2, οι απαιτήσεις γίνονται test cases την Εβδομάδα 6, και τα test cases γίνονται αυτοματοποιημένα tests την Εβδομάδα 8. Όταν μια νέα προδιαγραφή αλλάζει κάτι, ενημερώνετε τα προηγούμενα παραδοτέα και το καταγράφετε στο `quality/CHANGELOG.md`. Η διαχείριση αλλαγών αξιολογείται κι αυτή.

## Τι παραδίδετε

Ένα αποθετήριο Git ανά ομάδα (έως [N] άτομα), με πρόσβαση για τον διδάσκοντα. Οι απαντήσεις μπαίνουν στον φάκελο `quality/`, ένα αρχείο ανά εβδομάδα (`quality/w01.md`, `quality/w02.md`, …), μαζί με τα κοινά αρχεία που ενημερώνονται συνεχώς:

- `quality/risks.md` για τον κατάλογο κινδύνων,
- `quality/requirements.md` για τις απαιτήσεις,
- `quality/traceability.csv` για τον πίνακα ιχνηλασιμότητας,
- `quality/CHANGELOG.md` για τις αλλαγές.

Από την Εβδομάδα 4, tests και ρυθμίσεις εργαλείων μπαίνουν στον κώδικα του StudyRoom που θα σας δοθεί.

Για κάθε εβδομάδα υπάρχει υπόδειγμα στον φάκελο `templates/`, βασισμένο σε διεθνές πρότυπο (ISO/IEC/IEEE 29148, 29119-3, IEEE 1028 κ.ά.). Το αρχείο της εβδομάδας ξεκινά πάντα από το υπόδειγμα. Ο κατάλογος υποδειγμάτων και προτύπων βρίσκεται στο `templates/README.md`.

Κάθε εβδομάδα σημαδεύεται με tag (`w01`, `w02`, …) έως την Κυριακή 23:59 πριν την επόμενη διάλεξη. Στην αρχή κάθε αρχείου εβδομάδας γράφετε ποιο μέλος απάντησε σε ποιο ερώτημα.

## Βαθμολόγηση

Τα ερωτήματα κάθε εβδομάδας δεν βαθμολογούνται χωριστά. Βαθμολογούνται σε έξι ομάδες, σύμφωνα με τον πίνακα του κεντρικού `README.md` (σύνολο 40% του τελικού βαθμού), με τις ρουμπρίκες του `templates/RUBRICS.md`. Στο πρώτο βήμα κάθε ομάδας παραδοτέων παίρνετε γραπτή ανατροφοδότηση πριν τη βαθμολόγηση.

## Ερωτήσεις προς τον «πελάτη»

Ο διδάσκων παίζει τον ρόλο της βιβλιοθήκης. Ερωτήσεις για ασάφειες στις προδιαγραφές στέλνονται στο forum του eClass, στο νήμα «StudyRoom: ερωτήσεις προς τη βιβλιοθήκη», έως την Πέμπτη κάθε εβδομάδας. Οι απαντήσεις δημοσιεύονται εκεί για όλους και γίνονται μέρος των προδιαγραφών. Μην περιμένετε απάντηση σε ό,τι μπορείτε να αποφασίσετε μόνοι σας: τότε καταγράφετε την παραδοχή σας και προχωράτε.
