## Πώς λειτουργεί το εργαστήριο

Το μάθημα δεν έχει αυτοτελές εργαστήριο. Κάθε Δευτέρα, μετά τη θεωρία και τα λυμένα παραδείγματα, ακολουθούν περίπου 45 λεπτά καθοδηγούμενης εφαρμογής. Σε αυτά τα 45 λεπτά βλέπετε πρώτα την τεχνική της ημέρας λυμένη στο σύστημα αναφοράς `foodorder` (`labs/weekNN/SOLVED.md`) και μετά ξεκινάτε τα ερωτήματα της εβδομάδας στην εργασία εξαμήνου. Ό,τι δεν τελειώσει στην αίθουσα ολοκληρώνεται στο σπίτι.

## Η εργασία εξαμήνου: StudyRoom

Η εργασία είναι κοινή για όλους: ένα σύστημα κρατήσεων αιθουσών μελέτης για τη βιβλιοθήκη του Τμήματος, με το όνομα StudyRoom. Εσείς είστε η ομάδα ποιότητας του έργου. Κάθε Δευτέρα δημοσιεύεται στον φάκελο `assignment/` ένα αρχείο με νέες **προδιαγραφές** και νέα **ερωτήματα**. Οι προδιαγραφές μπορεί να είναι κείμενο του πελάτη, πρακτικά συνάντησης, αλλαγή απαίτησης ή κώδικας. Τα ερωτήματα ζητούν να εφαρμόσετε σε αυτές τις τεχνικές της εβδομάδας. Η εργασία χτίζεται σωρευτικά: ό,τι παραδίδετε μια εβδομάδα είναι η είσοδος της επόμενης. Λεπτομέρειες, τρόπος παράδοσης και ερωτήσεις προς τον «πελάτη» στο `assignment/README.md`.

Το `foodorder` δεν είναι η εργασία. Είναι το σύστημα πάνω στο οποίο δείχνουμε λυμένα παραδείγματα, ώστε να βλέπετε τη μορφή και το βάθος που περιμένουμε χωρίς να σας δίνουμε τις απαντήσεις του StudyRoom.

## Εγκατάσταση

Χρειάζεστε Python 3.10 ή νεότερη και Git.

```bash
git clone https://github.com/vtsakan/ece-inf950-quality-lab-2026.git
cd ece-inf950-quality-lab-2026/foodorder
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
pytest
```

Αν η τελευταία εντολή τυπώσει `3 passed`, το περιβάλλον είναι έτοιμο. Το ίδιο περιβάλλον θα χρησιμοποιήσετε για τον κώδικα του StudyRoom από την Εβδομάδα 4. Τα εργαλεία που εγκαθίστανται είναι pytest, pytest-cov, radon και ruff. Σε επόμενες εβδομάδες θα προστεθούν εργαλεία για API και performance testing.

## Βαθμολόγηση της εργασίας

| Ομάδα | Περιεχόμενο | Εβδ. | Βάρος στον τελικό βαθμό |
|---|---|---|---|
| Α | Quality plan, απαιτήσεις, ιχνηλασιμότητα | 1–3 | 5% |
| Β | Μετρικές, στατική ανάλυση, review | 4–5 | 8% |
| Γ | Σχεδιασμός test cases | 6–7 | 8% |
| Δ | Αυτοματοποιημένες δοκιμές, integration/API, debugging | 8–10 | 10% |
| Ε | Performance, CI, quality gate | 11–12 | 4% |
| ΣΤ | Τελική αναφορά και ατομική υποστήριξη | 13 | 5% |

Κάθε ομάδα παραδοτέων βαθμολογείται μία φορά, μετά την τελευταία της εβδομάδα. Τα εβδομαδιαία βήματα δεν βαθμολογούνται χωριστά, αλλά παίρνετε γραπτή ανατροφοδότηση στο πρώτο βήμα κάθε ομάδας. Έτσι προλαβαίνετε να διορθώσετε πριν τη βαθμολόγηση. Οι ρουμπρίκες βρίσκονται στο `templates/RUBRICS.md`. Κάθε εβδομάδα έχει υπόδειγμα παραδοτέου βασισμένο σε διεθνές πρότυπο· ο κατάλογος βρίσκεται στο `templates/README.md`.

## Παράδοση

Ένα αποθετήριο Git ανά ομάδα (έως [N] άτομα), με πρόσβαση για τον διδάσκοντα. Κάθε εβδομάδα σημαδεύεται με tag (`w01`, `w02`, …) έως τις 23:59 της Κυριακής πριν την επόμενη διάλεξη. Ό,τι υπάρχει στο tag είναι αυτό που διαβάζουμε. Η δομή του φακέλου `quality/` περιγράφεται στο `assignment/README.md`. Στην ατομική υποστήριξη της Εβδομάδας 13 κάθε μέλος εξηγεί και τα κομμάτια των άλλων· ο βαθμός μπορεί να διαφέρει ανάμεσα στα μέλη.

## Χρήση εργαλείων AI

Επιτρέπεται υποστηρικτική χρήση: εξήγηση εννοιών, πρώτο προσχέδιο test cases ή απαιτήσεων, αναδιατύπωση κειμένου. Κάθε χρήση δηλώνεται στο αρχείο `quality/AI_USE.md` με το εργαλείο, τον σκοπό, και τι κρατήσατε ή απορρίψατε. Ό,τι παράγει ένα εργαλείο το ελέγχετε: tests που περνούν χωρίς να ελέγχουν τίποτα και απαιτήσεις με λέξεις-παγίδες είναι τα συνηθισμένα αποτελέσματα. Κώδικας ή κείμενο που δεν μπορείτε να εξηγήσετε γραμμή προς γραμμή στην υποστήριξη δεν βαθμολογείται.
